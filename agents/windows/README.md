# NEXUS Native Agent 3.0.1 — Windows x64 developer preview

Single compiled GUI executable, no CMD or PowerShell installer. Per-user installation, no elevation required by design. Uses the existing NEXUS RC1 `/api/pair` and `/api/ingest` protocol. It does not open listening sockets, install a driver, modify the firewall, change Windows security settings, or contact another server except the explicitly configured HTTPS origin.

## Install
1. In NEXUS Devices, register a Windows profile and generate its one-time pairing code.
2. Run the x64 executable on a test Windows PC if Windows security policy permits execution. Confirm your server HTTPS origin. Enter the code.
3. If the certificate is already trusted by Windows, leave the optional CA fields blank. Otherwise transfer the public `nexus-ca.crt` from the administrator via a trusted channel; obtain its DER SHA-256 fingerprint independently (e.g. `openssl x509 -in .nexus/ca/ca.crt -noout -fingerprint -sha256` on the server). Select the CA file and paste the fingerprint value after `=`. Trust is restricted to this application; TLS hostname validation is still mandatory. Do not import unknown certificates or bypass TLS errors.
4. Click Install / Repair. Monitor starts now and at Windows sign-in under the current user. Double-click tray icon to reopen controls. Windows may hide the icon in its overflow section or disable startup via its settings. Pause/resume/repair/uninstall available in the UI. Repair without a new code retains the saved credential and CA for the same server. Pairing again to the same profile revokes its previous token, so only migrate an existing agent after verifying compatibility.

The native agent installs into `%LOCALAPPDATA%\NexusNativeAgent`. Do not run two agents using separate profiles for the same machine unless intentional. Uninstall removes own startup and application registration, credential and managed files; a temporary cleanup helper attempts to remove itself at reboot, which may require administrative rights. Original downloaded exe, other users' installs, and server profile/history remain. Revoke device access in NEXUS for server-side token invalidation. Do not remove the shared CA globally.

## Features and limits
CPU load, memory, system drive, uptime, CPU/model/OS build, interface receive/transmit rates (32-bit counters, approximate; may omit during long intervals), agent working set/CPU and optional first NVIDIA GPU via existing `nvidia-smi` in standard paths. No driver installation, CPU temperature/fans, FPS, AMD/Intel GPU load or automatic updates yet. Sampling approximately 10s, with backoff up to 60s after errors. Per-user sign-in autostart, not a Windows service that runs before login. No remote code execution or remote commands. Token is protected with Windows DPAPI under current user; this does not protect against compromise of that user account. Local server certificate validation is mandatory. Existing backend privacy filtering is server-side, not collection-side. RAM and CPU target still need measurement on real Windows.

## Build and tests
`go test -v .` on Linux tests transport, URL, pairing, ingestion, redirects and rejection of untrusted TLS. Cross-compile `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-H windowsgui -s -w' -o NEXUS-Agent-Setup-x64.exe .`. No third-party modules. Built with locally available Go 1.23.2; rebuild with currently supported Go and sign with a trusted code-signing certificate before public release. Cross-compilation does not test runtime Win32 calls. This development build is unsigned; do not weaken SmartScreen/Smart App Control/Defender to install it. A trusted signing identity and real Windows testing remain prerequisites for general release.
